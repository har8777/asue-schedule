# Ակադեմիական դասացուցակ

Համալսարանի ֆակուլտետների դասացուցակի կազմման և ցուցադրման համակարգ։

- **Ուսանողներ և դասախոսներ**. դիտում են դասացուցակը առանց մուտքի։ Հեռախոսում դասերը ցուցադրվում են օրերով, համակարգչում՝ աղյուսակով։ Կարելի է ներբեռնել PDF կամ ավելացնել Google/Apple օրացույց (.ics)։
- **Ֆակուլտետի ադմին**. խմբագրում է միայն իր ֆակուլտետի դասացուցակը։
- **Գլխավոր ադմին**. կառավարում է բոլոր ֆակուլտետները, օգտատերերին, պահուստային պատճենները և կարգավորումները։

## Տեխնոլոգիաներ

| Մաս | Տեխնոլոգիա |
|---|---|
| Frontend | React 19, TypeScript, Tailwind CSS 4, React Router 7, react-hook-form, axios, PWA (vite-plugin-pwa) |
| Backend | Node.js (≥ 22.18), TypeScript, SQLite (`node:sqlite`)։ **Արտաքին կախվածություններ չկան**, ուստի Windows-ում native build պետք չէ |

## Գործարկում (մշակման ռեժիմ)

```bash
npm install          # frontend-ի փաթեթները
npm run dev:server   # 1-ին տերմինալ. API-ն՝ http://localhost:4000
npm run dev          # 2-րդ տերմինալ. կայքը՝ http://localhost:5173
```

Առաջին գործարկման ժամանակ սերվերը ստեղծում է բազան (`server/data/schedule.db`), 6 ֆակուլտետները՝ կուրսերով, առարկաներով, դասախոսներով և լսարաններով, ինչպես նաև հաշիվները։ **Գաղտնաբառերը տպվում են կոնսոլում միայն մեկ անգամ**։ Պահպանեք դրանք։

| Մուտքանուն | Դեր |
|---|---|
| `superadmin` | Գլխավոր ադմին (գաղտնաբառը՝ `SUPER_ADMIN_PASSWORD`-ից կամ պատահական) |
| `karavarum`, `finans`, `tntesagitutyun`, `marketing`, `hashvapah`, `informatika` | Համապատասխան ֆակուլտետի ադմին |

Գաղտնաբառը փոխելու համար օգտագործեք ադմինի մենյուի «բանալի» կոճակը։ Գլխավոր ադմինը կարող է փոխել ցանկացած օգտատիրոջ գաղտնաբառը «Օգտատերեր» բաժնում։

## Արտադրական տեղադրում

```bash
npm install
npm run build        # TypeScript ստուգում + կայքի կառուցում (dist/)
cp server/.env.example server/.env   # լրացրեք SUPER_ADMIN_PASSWORD, NODE_ENV=production
npm start            # սերվերը մատուցում է և՛ կայքը, և՛ API-ն՝ նույն պորտում (4000)
```

- Սերվերը կարող է աշխատել ցանկացած VPS-ում (pm2 կամ systemd)։ Դրա առջևում դրեք nginx՝ HTTPS-ով (PWA-ն պահանջում է HTTPS) և միացրեք `TRUST_PROXY=true`։
- **GitHub Pages-ն այլևս հարմար չէ**, որովհետև այն չի կարող գործարկել սերվեր։ Եթե frontend-ը, միևնույն է, առանձին է տեղադրվում, նշեք `VITE_API_URL` (frontend) և `CORS_ORIGINS` (server)։
- Պարբերաբար պատճենեք `server/data/` թղթապանակը կամ օգտվեք «Պահուստավորում» էջից։

## Հին տվյալների տեղափոխում

Հին տարբերակում դասացուցակը պահվում էր միայն բրաուզերում։ Այն տեղափոխելու համար.

1. Հին կայքում մուտք գործեք որպես superadmin և սեղմեք **«📥 Backup JSON»** (DEV TOOLBAR-ում)։
2. Նոր կայքում բացեք **Կառավարում → Պահուստավորում → Վերականգնել / ներմուծել** և ընտրեք այդ ֆայլը։

Դասերը կավելացվեն համապատասխան ֆակուլտետներին և կուրսերին։ Անհրաժեշտության դեպքում հոսքերը և օրերը կավելացվեն ավտոմատ։

## Դասացուցակի կանոններ

- **Համարիչ / Հայտարար**. դասաժամը բաժանվում է կեսերի։ Ամբողջական դասը զբաղեցնում է ամբողջ դասաժամը, իսկ բաժանված դասի յուրաքանչյուր մաս՝ իր կեսը։ Նույն դասախոսը կամ լսարանը չի կարող կրկնվել նույն վանդակի մի քանի մասում։
- **Մասնաշենքեր**. յուրաքանչյուր ֆակուլտետ ունի իր մասնաշենքը։ Տարբեր ֆակուլտետների նույն համարով լսարանները (օր.՝ 202) տարբեր լսարաններ են։
- **Զբաղված լսարան**. նույն մասնաշենքում նույն ժամին արդեն զբաղված լսարանը **հնարավոր չէ** նշանակել։
- **Զբաղված դասախոս**. ցուցադրվում է զգուշացում։ Ադմինը կարող է հաստատել և պահպանել («Պահպանել միևնույն է»)։
- **Ձեռքով նշված լսարան**. լսարանը, որը չկա ֆակուլտետի ցուցակում, պահպանվում է միայն տվյալ դասում («ժամանակավոր») և չի ավելանում տեղեկատուին։ Լսարանների մշտական ցուցակը կառավարվում է «Տեղեկատու» էջից։ Նոր առարկաներն ու դասախոսները ավելանում են տեղեկատուին ավտոմատ։

## Թեստեր

```bash
npm test             # API-ի ինտեգրացիոն թեստեր (դերեր, բախումներ, պահուստավորում)
npm run typecheck    # TypeScript ստուգում (frontend)
```

## Կառուցվածք

Կոդը բաժանված է ըստ մոդուլների։ Ֆայլերի անունները kebab-case են՝ `{name}.{role}.ts`։

```
src/
  app/                      # router, route-երի աղյուսակ, provider-ներ
  modules/
    auth/                   # auth.constants.ts, auth.requests.ts, auth.context.tsx, guards/, pages/
    schedule/               # schedule.types.ts, schedule.requests.ts, schedule.utils.ts, components/, hooks/, services/, pages/
    faculties/ catalog/ reports/ change-log/ users/ backup/ settings/ dashboard/
    common/                 # http-client (axios), UI կոմպոնենտներ, layout-ներ, hooks
server/src/
  core/                     # http router, database, security (JWT, scrypt), validation
  modules/                  # նույն սկզբունքով՝ {name}.repository.ts, {name}.service.ts, {name}.controller.ts
  seed/                     # սկզբնական տվյալներ
```

Կիրառված սկզբունքներ.

- **Repository → Service → Controller** շերտեր (SRP)։
- Կախվածությունները միացվում են մեկ տեղում՝ `server/src/app.ts` (Dependency Injection)։
- `httpClient`-ը չգիտի auth-ի մասին. token-ը գրանցվում է auth մոդուլից (DIP)։
- Հետարկել/Կրկնել գործողությունները կառուցված են **Command** pattern-ով։
- Guard-երը կազմված են փոքր, իրար հետ համադրվող բաղադրիչներից (`RequireAuthGuard`, `RequireRoleGuard`, `GuestOnlyGuard`)։
- Իրավունքները ստուգվում են **սերվերում**։ Frontend-ի guard-երը միայն թաքցնում են անհասանելի էջերը։
